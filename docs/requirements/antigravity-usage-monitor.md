# Antigravity Usage Monitor

- 状态：已对齐
- 更新时间：2026-11-23

## 目标
- 参考 `kittors/claude-usage-monitor` 的设计思路，构建一个本地编译、自签的原生 macOS（Swift 6）菜单栏统计 App。
- 不依赖抓包、不读取未公开接口或 Keychain，仅基于 Antigravity 官方 CLI（`agy`）的 `statusLine` 机制与本地 `transcript.jsonl` 对话日志，直观展示官方 5 小时限额、周限额、缓存命中、输入/输出 Token、按模型分布、14 天趋势、活跃上下文窗口及 API 等价费用估算。

## 非目标
- 不做网络抓包、逆向或调用未公开后端 API。
- 不管理账号登录态、不做 Token 自动续期、不做网络出口/代理地区检测。
- 不修改或干预 Antigravity 的对话流程，仅做只读统计与展示（桥接配置除外）。

## 已确定的决策

### D1：采用双源融合数据架构
- 决定：同时使用两个官方/本地数据源——增量解析本地 `transcript.jsonl` 负责全量历史 Token、缓存、按模型拆分、14 天趋势与费用估算；通过 `agy` CLI 官方 `statusLine` 桥接脚本落盘 JSON 快照，负责官方 5 小时限额、周限额、重置倒计时与活跃会话上下文窗口。
- 理由：既能做到零抓包、零 429 频控风险，又能同时获得官方真实限额百分比与跨会话的全量 Token/缓存统计。接受的取舍是官方限额快照仅在使用 `agy` CLI 期间更新。
- 否掉的方案：纯本地日志（拿不到官方真实剩余百分比与官方重置时间）；纯 `statusLine` 快照（无法统计跨会话历史 Token 与缓存汇总）。
- 来源：用户确认

### D2：首版功能范围（核心 + 全部四项增强）
- 决定：首版包含核心模块（官方 5 小时/周限额与倒计时、今日/本周/近 5 小时输入/输出/缓存 Token 与缓存命中率），并全部纳入四项增强模块：安全配速线（Safe Line）、按模型拆分与 14 天趋势图、当前活跃会话上下文窗口占比、API 等价费用与缓存省钱估算。
- 理由：完整对齐 `claude-usage-monitor` 的核心观测体验，兼顾配额预警、缓存效率与成本体感。
- 来源：用户确认

### D3：`agy statusLine` 桥接采用 App 内置「一键接入 / 一键还原」
- 决定：App 启动检测到未接入时提供一键配置引导；自动备份 `~/.gemini/antigravity-cli/settings.json`，未配置过自定义 `statusLine` 时写入桥接脚本并启用 `stack_with_default: true` 保留官方默认状态栏；若检测到用户已有自定义 `statusLine` 脚本，自动生成包装脚本链式调用原脚本，绝不覆盖原有配置，并支持随时一键还原。
- 理由：降低手动配置门槛，同时保证对用户现有 CLI 配置零破坏且可逆。
- 否掉的方案：纯只读手动配置（上手繁琐）。
- 来源：用户确认

### D4：复刻 `claude-usage-monitor` 的菜单栏 Popover 与独立设置窗交互
- 决定：采用纯菜单栏常驻 App（不在 Dock 显示图标）；菜单栏支持按需勾选叠加列（默认 5 小时限额，可选周限额、缓存命中率、今日估算费用、当前上下文占比，按水位/安全配速线自动变色）；弹出面板各区块支持「详细 / 简洁 / 隐藏」三档切换与点击标题折叠；配备独立设置窗口与开机自启开关。
- 理由：兼顾日常零打扰常驻与按需查看完整细节的体验，最贴合参考项目的交互手感。
- 否掉的方案：极简固定布局（信息密度和菜单栏列不可定制）。
- 来源：用户确认

### D5：边界与异常严格区分官方值与本地值
- 决定：`statusLine` 快照过期时保留上次官方值并标注「更新于 X 分钟前」，到达 `reset_time` 时本地自动归零；从未同步时限额区置灰提示运行一次 `agy` 即可同步，绝不用本地 Token 冒充官方百分比。本地 `transcript.jsonl` 遇到内置价格表未收录的新模型时，正常计入 Token 与缓存统计，费用区明确标注「含未定价模型」而不编造单价。
- 理由：保持数据诚实度，避免真实配额与估算数字混淆，与 `claude-usage-monitor`「官方数字绝不靠猜」的原则一致。
- 否掉的方案：本地估算兜底替代官方百分比与近似单价折算。
- 来源：用户确认

### D6：工程构建与自签打包采用 SwiftPM + Makefile
- 决定：采用纯 Swift 6 + SwiftPM（零第三方依赖），拆分为无 UI 的 `UsageCore`（含完整 `swift test` 单元测试）与 macOS 菜单栏 App 目标；通过 `Makefile` 与构建脚本一键编译、组装 `.app` 并默认执行 ad-hoc 自签（`codesign --force --deep --sign -`），同时支持通过 `CODESIGN_IDENTITY` 环境变量切换本机自建代码签名证书。
- 理由：与 `kittors/claude-usage-monitor` 结构一致，命令行一键可复现、测试轻快、无 Xcode 工程文件维护负担。
- 否掉的方案：Xcode 工程（`.xcodeproj`）打包。
- 来源：用户确认
